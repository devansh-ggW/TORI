01 / PRODUCT

A business brain, not a chatbot.

TORI is built around recurring business questions. Products, services, prices, policies, aliases and preferred language become a structured knowledge pack the engine can use without requiring a heavyweight model.

A / KNOWLEDGE

One source of truth

Store products, services, prices, links, delivery rules, support answers and custom terminology in one inspectable business pack.

B / INTENT

Meaning over one keyword

Patterns, nearby words, aliases, quantities and entities work together so different ways of asking can reach the same business intent.

C / CONFIDENCE

Never guess silently

Green means confirmed. Yellow means review. Red means unconfirmed. Missing facts stay visible instead of becoming invented answers.

02 / CORE

Small engine. Serious job.

The initial Core is deliberately lightweight JavaScript: deterministic rules, contextual scoring and explicit business knowledge. The same engine can sit beneath desktop first and mobile later.

Normalize

Clean casing and punctuation, tolerate common typos and preserve meaningful tokens.

Pattern matching

Recognize “how much”, “price of”, “kitne ka”, “available”, “send the link” and related forms.

Entity resolution

Resolve “vault”, “cv300” and other aliases against the actual products and services in the local pack.

Context scoring

Words near intent signals contribute to confidence while missing context lowers certainty.

Grammar tolerance

“how much it cost” can still be a strong price signal. Language quality and meaning confidence are separate.

User teaching

Corrections become explicit rules. The system can grow without hiding its logic inside an opaque model.

07 / FAQ

Clear by design.

The initial system is local-first, explicit and confidence-driven. The website itself requires no server.

Is TORI a large AI model?
No. The first Core is a JavaScript rules-and-knowledge engine focused on the recurring language of a specific business.
Does the Core need a server?
The Core Lab does not. It runs in the browser and stores its demo pack locally. Future account synchronization can be separated from the reasoning layer.
What do green, yellow and red mean?
Green is a high-confidence match. Yellow is a plausible interpretation that needs review. Red means the current knowledge or message context is not sufficient for a reliable suggestion.
Does bad grammar always reduce confidence?
No. TORI separates language quality from intent. Rough wording can still be clear enough for a strong match.
Can the website be published without a server?
Yes. This file contains the markup, styling and JavaScript required for the site. It can be published on GitHub Pages or another static host.
